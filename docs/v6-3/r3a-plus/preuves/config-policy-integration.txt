DEFECT FOUND DURING PARENT INTEGRATION
A2 was based on the pre-WSS branch and documented/validated a loopback-only
relay URL policy. After A1's integration, relay-link.ts accepts remote wss://
and allows ws:// only on exact loopback with ATLAS_ALLOW_LOOPBACK_WS=1. The
operational config checker still rejected wss:// remote and did not allow the
ATLAS_ALLOW_LOOPBACK_WS key, which would have blocked the primary R3-A+ goal.

CORRECTION
- config.mjs validates: wss:// remote accepted; ws:// only on 127.0.0.1,
  localhost, or ::1 with ATLAS_ALLOW_LOOPBACK_WS=1; credentials, query,
  fragment, arbitrary paths and invalid hosts/ports rejected.
- ATLAS_ALLOW_LOOPBACK_WS is an allowed environment key and must be 0 or 1.
- check-config explains the WSS/loopback policy and keeps FastAPI loopback-only.
- README and INSTALLATION_PC.md now document remote WSS and the local ws opt-in.
- verify-install.sh runs the new policy check after build.
