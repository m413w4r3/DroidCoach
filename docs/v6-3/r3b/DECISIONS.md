# ATLAS V6.3 — R3-B — Décisions techniques

Décisions réversibles prises par le parent, tracées ici. Toute divergence
d'implémentation doit être signalée au parent avant intégration.

| ID | Décision | Justification | Réversibilité |
|---|---|---|---|
| D-R3B-01 | `ATLAS_RELAY_URL=wss://all.taildc7886.ts.net:8443`, sans `/ws`, sans token, sans `serverId` | `RelayConfig.webSocketUrl()` et le connecteur construisent `/ws` et les paramètres Paseo v2 ; le port 8443 est celui du Funnel TLS-terminated TCP | changer la variable d'environnement et le champ Android |
| D-R3B-02 | Relais Paseo épinglé sur `127.0.0.1:4402` ; proxy filtrant sur `127.0.0.1:4400` | le Funnel pointe déjà sur 4400 ; le relais reste inchangé et non exposé directement | arrêter le proxy, relancer le relais sur un autre port |
| D-R3B-03 | Proxy en Node 24, modules standard uniquement | surface minimale, aucune dépendance transitive nouvelle, contrôle explicite de l'upgrade et des limites | remplacer le binaire sans changer les contrats |
| D-R3B-04 | Proxy : `GET /health`, `GET /ready`, upgrade `GET /ws` uniquement ; `v=2` obligatoire ; clés de requête `serverId`, `role`, `v`, `connectionId` uniquement | ferme `/metrics`, les autres chemins, les méthodes non GET et le mode relais v1 legacy | élargir la liste blanche après revue |
| D-R3B-05 | Aucun TLS local entre Funnel et proxy | Tailscale termine le TLS public ; Noise NK reste de bout en bout ; un TLS loopback redondant ajouterait des secrets et de la complexité | ajouter un terminateur local si le modèle de menace change |
| D-R3B-06 | Capacité `coach.chat`, opération `coach.chat.request`, protocole `atlas.remote.v1` conservé | extension additive : les anciens clients et appareils appairés sans la capacité restent valides | retirer l'opération et la capacité |
| D-R3B-07 | `coach.chat.request` est une opération à effet : journal d'idempotence, résultat incertain non rejoué automatiquement | la déduplication de bout en bout n'est pas démontrée ; un POST incertain ne doit pas produire un second appel | repasser l'opération en lecture seule après preuve de déduplication |
| D-R3B-08 | Rejeu strictement identique (même `request_id`/`idempotency_key`, même payload) : réponse mémorisée `replayed=true` ; payload différent : `IDEMPOTENCY_CONFLICT` ; résultat incertain : `BACKEND_UNAVAILABLE` non retentable | empêche les doublons sans prétendre à une idempotence non prouvée | ajuster la fenêtre de cache |
| D-R3B-09 | Android : en mode `RELAY`, le chat utilise `coach.chat.request` ; en `DIRECT`, le HTTP existant ; en `OFFLINE`, le mock local | aucun second écran, aucun nouveau parcours ; la provenance reste visible | changer le routage du contrôleur |
| D-R3B-10 | La provenance `mock` / `OpenClaw personnel` est affichée dans la conversation et provient de `agent_status` renvoyé par FastAPI | l'utilisateur doit distinguer une démonstration d'une vraie réponse distante | ajuster les libellés UI |
| D-R3B-11 | A4 : la révocation PC conduit à `REVOKED`, puis l'effacement local des credentials est une action explicite de l'utilisateur ; la relance ne réappaire pas implicitement | conserve la maîtrise utilisateur et évite toute suppression silencieuse | automatiser l'effacement après confirmation explicite |
| D-R3B-12 | Aucun FCM, aucune promesse de réception instantanée en arrière-plan | hors périmètre R3-B ; Doze doit être mesuré, pas supposé | campagne push séparée |
| D-R3B-13 | Le Pixel physique `$PIXEL_SERIAL` est la cible de qualification réelle, avec sauvegarde app-only avant toute installation | autorisation explicite de l'utilisateur ; aucune donnée personnelle ne doit être perdue | restaurer la sauvegarde et l'APK précédent |
| D-R3B-14 | Tests réseau réels : LTE/5G avec Wi-Fi désactivé, sans `adb reverse` ni proxy USB ; état restauré après test | le Funnel public est le seul chemin autorisé pour la preuve Internet | réactiver les interfaces |
| D-R3B-15 | Instance FastAPI de test isolée sur `127.0.0.1:8100` avec jeton de service synthétique ; l'OpenClaw personnel n'est utilisé qu'en lecture/chat, sans modification de configuration | préserve les services personnels et permet les tests reproductibles | arrêter l'instance de test |
| D-R3B-16 | wger réel en lecture seule uniquement si le jeton existant le permet ; aucun token affiché, aucune écriture, aucun renouvellement | le `.env` privé contient déjà un token ; sinon `BLOCKED_AUTH` | retirer le test réel |
| D-R3B-17 | Le relais et le proxy sont testés comme services isolés ; aucune installation systemd persistante ni `linger` pendant la campagne | limite d'autorisation explicite de la mission | installer après autorisation ciblée |
| D-R3B-18 | Avant la fermeture 4001, le connecteur attend 200 ms bornés après l'envoi de `DEVICE_REVOKED` | le relais doit router la trame sur la connexion de données avant la fermeture ; sans cette grâce, le test A4 pouvait manquer la trame | ajuster ou retirer la constante `REVOKE_GRACE_MS` |
| D-R3B-19 | Le test réseau du connecteur accepte `RELAY_CONNECTING` comme état de coupure, en plus de `OFFLINE`/`ERROR` | l'arrêt du connecteur laisse le relais joignable ; l'app peut rester en reconnexion ; l'état observé final est `ERROR` | condition test-only, aucun impact produit |
| D-R3B-20 | Au recontrôle public final, si l'ingress public est indisponible pour une cause réseau externe, rejouer l'E2E via le nom Funnel/MagicDNS et documenter la limite | ne pas modifier la configuration Tailscale personnelle ; distinguer le code du réseau | rejouer l'E2E public quand la connectivité Tailscale revient |
| D-R3B-21 | Restauration finale par sauvegarde app-only complète (force-stop, purge des répertoires de données, extraction tar), puis vérification des 5 hashes et du calendrier | retour à l'état d'avant campagne sans `pm clear`, sans désinstallation, sans toucher au Keystore | réappliquer la sauvegarde |
| D-R3B-22 | wger réel non exécuté : l'autorisation explicite manque, même si un token existe dans le `.env` privé | la mission exige une autorisation pour toute lecture externe non couverte ; aucun contournement | exécuter une lecture seule après autorisation ciblée |
| D-R3B-23 | Le consentement est revalidé au dispatch par `AgentContextSnapshot.stillAllows()` + `AgentContextCoordinator.consentStillAllows()`, sans reconstruire les domaines ni réécrire l'audit | ferme le P1 de consentement périmé sans réintroduire le risque de deadlock de l'audit sous verrou | retirer le contrôle `snapshotStillAuthorized` |
| D-R3B-24 | Le connecteur accorde l'intersection des capacités demandées et stockées ; un ancien appareil sans `coach.chat` reste connecté et reçoit `OPERATION_UNAVAILABLE` pour le chat | compatibilité additive des anciens appairages, capacité stockée autoritaire | rétablir le rejet strict après migration des appareils |
| D-R3B-25 | Le transport expose `lastCloseCode` et `clear()` supprime l'alias Keystore `atlas_relay_device_v1` ; le test A4 affirme 4001 et l'absence d'alias | rend vérifiables A4-4/A4-8 et ne laisse pas de clé réutilisable après désappairage | retirer l'exposition de diagnostic et conserver l'alias |
| D-R3B-26 | Le re-test Pixel de l'APK final est reporté tant que l'ingress public Funnel est indisponible ; le verdict distingue le code validé JVM/Node des parcours Pixel de l'APK antérieur | ne pas modifier Tailscale ni présenter un test non exécuté comme PASS | rejouer A3/A4/chat sur le Pixel dès le retour de l'ingress |
| D-R3B-27 | Un `AgentConsentGate` partagé (ReentrantLock) est tenu par le transport du contrôle avant dispatch jusqu'à l'écriture WebSocket ; les mutations de consentement, d'objectifs et de barrière prennent le même verrou | ferme la course résiduelle identifiée par la revue 2 entre le contrôle et la trame | remplacer par une reconstruction atomique au dispatch |
| D-R3B-28 | La révocation annule immédiatement les opérations en vol ; la grâce de 200 ms ne retarde que la fermeture de la socket | arrête les effets backend sans perdre la course d'acheminement de `DEVICE_REVOKED` | réduire/retirer la grâce après preuve d'un acquittement explicite |
| D-R3B-29 | L'APK final `05756094` n'a pas été installé : le Pixel s'est déconnecté de l'USB ; l'APK `1a877422` reste installé | ne pas présenter une installation ou un test Pixel non exécuté comme PASS | réinstaller et rejouer dès reconnexion |
| D-R3B-30 | `revokeUsageObservation()` mute le consentement d'usage et les capacités sous `AgentConsentGate` | ferme la dernière mutation de consentement de domaine non sérialisée avec le dispatch (revue 3) | retirer le verrou de cette méthode |
| D-R3B-31 | Sur le chemin `receive()` `DEVICE_REVOKED`, les opérations en vol sont annulées avant l'attente de `sendError()` | évite qu'un effet backend survive à la révocation pendant une écriture lente | réordonner après un test de canal bloquant |
