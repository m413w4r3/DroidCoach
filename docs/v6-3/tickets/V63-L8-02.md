## Objectif observable

Construire et valider **hors activation** un plugin OpenClaw
`atlas_chatgpt_research` qui expose un seul outil de recherche au Bridge
ChatGPT, retourne un résultat structuré avec provenance et limites, et ne
déclenche aucune action ATLAS. Aucun redémarrage OpenClaw, aucune modification
de `~/.openclaw/openclaw.json`, aucune installation de plugin dans ce ticket.

## Outil unique

Nom : `atlas_chatgpt_research`, `optional: true`.

Paramètres abstraits et bornés (aucune donnée intime) :
- `topic` ou `question` (1..500) ;
- `goal` (≤ 120) ;
- `language` (≤ 16) ;
- `freshness` (`any|week|month|year`) ;
- `max_results` (1..8).

Retour structuré :
```text
{
  summary, facts[],
  citations[{label, url, canonical_url?}],
  search_mode: ui_tool|prompt_instructed|off|off_unverified|untouched,
  verified_search: bool,          // true seulement pour ui_tool
  status: completed|failed|uncertain|unavailable,
  limitations[], run_id, request_id
}
```
Aucune commande, aucun script, aucune instruction exécutable. Toute réponse et
citation est une **donnée non fiable**.

## Client Bridge

- `POST {bridgeUrl}/v1/bridge/runs` avec `input` texte, `web_search: true`
  lorsque `freshness != any`, `background: true`, `request_id` stable.
- `X-Idempotency-Key` = même valeur que `request_id`.
- `request_id` = `context.toolCallId` (stable pour l'appel d'outil).
- Poll `GET /v1/bridge/runs/{id}` avec backoff borné (1 s → 5 s), deadline
  globale ≤ 30 min, `context.signal` respecté.
- Gérer `401`, `409`, `429` + `Retry-After` borné, `5xx`, timeout, `404`,
  `needs_review`, JSON malformé.
- Résultat ambigu après soumission : reprendre le **même** run par `id` ou clé
  d'idempotence ; jamais une seconde génération aveugle.
- `verified_search = (metadata.web_search_mode == "ui_tool")` ; ne jamais
  affirmer une fraîcheur ou une fiabilité de source au-delà de cette preuve.
- Citations uniquement depuis `metadata.visible_citations` ; ne jamais inventer
  de lien, de date ou de métadonnée.
- Validation TypeBox de la sortie ; échec = résultat refusé, pas de partiel.

## Porte d'activation (parent/propriétaire)

Après acceptation du plugin, l'activation exige un accord ciblé pour :
1. installer le plugin (`openclaw plugins install <path>` ou `--link`) ;
2. modifier la politique des agents (planificateur limité à `sessions_spawn`,
   agent `atlas-research` limité à `atlas_chatgpt_research`) ;
3. redémarrer/recharger le Gateway ;
4. exécuter une recherche réelle et qualifier `ui_tool` vs
   `prompt_instructed`.

Sans accord : plugin livré mais **non activé**, `BLOCKED_POLICY` pour le
parcours discussion → recherche.
