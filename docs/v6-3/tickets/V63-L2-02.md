## Objet et limite d'autorisation

Préparer **le patch** qui déclare `READ_CALENDAR` et ajoute un écran de
diagnostic des calendriers. Le patch ne doit **pas** être installé sur le Pixel,
aucune permission runtime ne doit être accordée, aucun calendrier ne doit être
lu sur l'appareil avant l'accord ciblé du propriétaire. L'écran et le manifeste
restent dans le worktree jusqu'à revue et approbation.

## Contenu

1. `android/app/src/main/AndroidManifest.xml` : ajouter uniquement
   `android.permission.READ_CALENDAR` (pas `WRITE_CALENDAR` dans ce ticket).
2. `CalendarPermissionScreen.kt` :
   - état de la permission (`GRANTED`, `DENIED`, `NOT_DECLARED`) ;
   - explication minimale et révocable ;
   - bouton explicite « Autoriser la lecture du calendrier » via
     `rememberLauncherForActivityResult(RequestPermission)` ;
   - après accord, liste les calendriers via `CalendarReadService` :
     nom d'affichage, compte masqué/expurgé, niveau d'accès, visibilité ;
   - affiche la présence d'Etar (`ws.xsoh.etar`, `.debug`) ;
   - aucun événement, aucun contenu personnel, aucune écriture.
3. `CalendarReadConsent.kt` (nouveau) : consentement local ATLAS explicite,
   stocké séparément, révocable ; la lecture est refusée si le consentement est
   absent même si la permission OS est accordée.
4. Tests JVM : états de permission, refus sans requête, consentement absent,
   mapping des calendriers, aucune fuite de données dans les logs.
