## Objectif observable

Étendre le système visuel existant avec **quatre palettes d'accent sobres**,
une préférence persistante **indépendante** des quatre modes clair/sombre,
des rôles sémantiques cohérents, et des primitives d'état qui ne dépendent pas
de la couleur seule. Aucune régression des préférences stockées, aucun
changement de l'identité ATLAS par défaut.

android/app/src/test/java/dev/atlas/coach/app/ui/**

## Exigences

### 1. Palettes d'accent

- Enum stable et persistée :
  - `CLASSIC` — « ATLAS classique » (ambre/bronze existant, **défaut**) ;
  - `FOREST` — « Forêt » (vert doux) ;
  - `OCEAN` — « Océan » (bleu minéral) ;
  - `SLATE` — « Ardoise » (bleu-gris désaturé).
- Valeurs de stockage stables (`classic`, `forest`, `ocean`, `slate`) ;
  valeur absente/inconnue → `CLASSIC`.
- L'accent ne remplace que les rôles d'accent (primary/secondary et leurs
  conteneurs) ; les surfaces, le fond et les textes restent ceux du mode.
- Le mode `AMOLED` conserve `background = 0xFF000000` et `surface = 0xFF000000`.
- Les quatre modes existants (`DARK`, `AMOLED`, `FOLLOW_SYSTEM`, `LIGHT`) et
  leurs valeurs stockées sont inchangés.
- L'accent `CLASSIC` en mode sombre doit produire exactement les tokens
  d'accent actuels (`primary 0xFFB49A63`, etc.).

### 2. Préférence persistante

- Store `SharedPreferences` séparé (`atlas_accent_preference` ou nom explicite
  équivalent), même style que `ThemePreferenceStore` : lecture au démarrage,
  écriture immédiate, écoute des changements.
- Codec pur testable en JVM, sans `android.content`.
- Le choix du mode et celui de l'accent sont indépendants : changer l'un ne
  modifie pas l'autre.
- La préférence survit à la fermeture/réouverture (vérification instrumentée
  par le parent).

### 3. Couleur dynamique Android (optionnelle mais exigée si compatible)

- Option explicite « Couleurs dynamiques Android », disponible uniquement sur
  API ≥ 31 ; sur API < 31, l'option est absente ou désactivée avec un texte
  clair.
- Quand elle est active, utiliser `dynamicDarkColorScheme` /
  `dynamicLightColorScheme` ; l'accent ATLAS n'est pas appliqué et l'UI
  l'indique.
- Ne jamais activer dynamique par défaut ; ne jamais écraser AMOLED sans choix
  explicite.
- Si l'implémentation s'avère impossible sans modifier les call sites, livrer
  l'option désactivée et documenter la limite ; ne pas casser la compilation.

### 4. Rôles sémantiques

Exposer des tokens nommés et stables :

- `accent` (action principale/sélection) ;
- `success` (progression confirmée) ;
- `warning` (conflit/attention) ;
- `error` (échec/permission refusée) ;
- `neutral` (non effectué/indisponible) ;
- `category` (marqueurs discrets et stables par type d'activité).

Chaque rôle doit avoir un couple texte/fond vérifié. Les rôles ne doivent pas
être redéfinis écran par écran.

### 5. Statut non dépendant de la couleur seule

Modifier `AtlasStatus` pour afficher un **glyphe distinct** par
`AtlasStatusKind` (par exemple `●`, `◉`, `◌`, `!`) en plus du libellé et de la
barre. Le `contentDescription` doit inclure le libellé. Aucun état ne doit
être indiqué uniquement par une teinte.

### 6. Section de réglages

Étendre `ThemePreferenceSection` :

- modes existants (radio, 48 dp, sémantique) ;
- « Palette d'accent » avec les quatre choix et leur libellé ;
- aperçu immédiat ;
- option dynamique si API ≥ 31 ;
- textes courts, pas de paragraphe technique.

## Oracle (obligatoire)

Tests JVM à ajouter dans `app/src/test/java/dev/atlas/coach/app/ui/` :

1. `missingOrUnknownAccentFallsBackToClassic`
2. `eachAccentHasStableStorageValueAndLabel`
3. `accentAndModeAreIndependent`
4. `classicDarkKeepsExistingAccentTokens`
5. `amoledKeepsPureBlackBackgroundForEveryAccent`
6. `everyModeAccentPairMeetsWcagAaForNormalText` — 4 accents × 3 palettes de
   base (`dark`, `amoled`, `light`) × toutes les paires de
   `textContrastPairs()` ≥ 4.5.
7. `semanticRolesHaveAccessibleContrast` — paires sémantiques ≥ 4.5 pour le
   texte normal, ≥ 3.0 pour les éléments non textuels.
8. `semanticRolesAreDistinct` — success/warning/error/neutral non confondus
   par leurs valeurs ARGB.
9. `statusGlyphsAreDistinctForEveryKind`
10. `dynamicColorFallsBackSafelyWhenUnsupported` (fonction pure de décision).
