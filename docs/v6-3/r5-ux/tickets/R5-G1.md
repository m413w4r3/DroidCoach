## Objectif observable

Produire une synthèse **déterministe et locale** des 7 derniers jours et du mois passé (jour, semaine, mois) à partir de faits fournis par l'app : sessions Focus, historique d'habitudes, activités planifiées, objectifs et effets d'agent. Aucune tendance inventée : si les données sont insuffisantes, la sortie le dit explicitement.

## Contrat proposé (à ajuster sans sortir du périmètre)

```kotlin
enum class InsightPeriod { DAY, WEEK, MONTH }

data class InsightFacts(
    val nowUtcMillis: Long,
    val zoneId: ZoneId,
    val focusSessions: List<FocusFact>,
    val habitHistories: List<HabitFact>,
    val planDays: List<PlanDayFact>,
    val goals: List<GoalFact>,
    val agentEffects: List<EffectFact>,
)
```

- `FocusFact` : début UTC, statut terminal, cycles terminés, secondes de travail, titre de tâche.
- `HabitFact` : nom, jours dus/faits (epochDay), série courante.
- `PlanDayFact` : date locale, activités (titre, type, statut, priorité).
- `GoalFact` : titre, métrique, cible, valeur courante, statut, échéance.
- `EffectFact` : type d'action, état terminal, horodatage.
- Sortie : `CoachInsightReport(period, enoughData, metrics, observations, insufficientReasons)` avec des textes courts en français, des libellés structurés et **aucun chiffre non dérivé des faits**.

## Règles de calcul et seuils (obligatoires, testés)

1. **Jour** : fenêtre = jour local courant. Métriques : minutes Focus terminées, cycles, activités `DONE` / `MISSED` / prévues, habitudes cochées / dues, objectifs actifs. `enoughData=false` si aucune donnée du tout → `Données insuffisantes`.
2. **Semaine** : 7 jours locaux glissants incluant aujourd'hui. `enoughData=false` si moins de **3 jours** avec au moins une donnée.
3. **Mois** : 30 jours locaux glissants. `enoughData=false` si moins de **7 jours** avec au moins une donnée.
4. **Patterns** : n'émettre une observation que si elle est purement factuelle et au-dessus d'un seuil :
   - jour le plus actif en minutes Focus (seulement si ≥ 2 jours avec sessions) ;
   - taux de réalisation des activités planifiées (seulement si ≥ 5 activités terminées/manquées) ;
   - habitude la plus régulière sur la fenêtre (seulement si ≥ 2 habitudes avec ≥ 3 jours dus) ;
   - aucune causalité, aucun conseil médical, aucune comparaison morale.
5. **Déterminisme** : tri stable (date, puis identifiant), aucun `Random`, aucun accès réseau, aucun `Android.*`, aucun `System.currentTimeMillis()` interne (le temps est injecté).
6. **Fuseau** : les fenêtres sont calculées en `LocalDate` via `ZoneId` fourni ; tester un changement d'heure et un fuseau non-UTC.
7. **Données partielles** : une session `CANCELLED` ne compte pas comme temps Focus terminé ; elle peut être comptée comme interruption factuelle. Ne jamais extrapoler une moyenne sur des jours sans données.
