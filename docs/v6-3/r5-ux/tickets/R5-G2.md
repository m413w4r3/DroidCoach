## Objectif observable

Le bas d'écran `Coach` ouvre un sous-onglet **`Conversation · Synthèses`**. `Synthèses` affiche, pour **Jour / Semaine / Mois**, les agrégats locaux produits par `R5-G1` : temps Focus, cycles, activités terminées/manquées, habitudes, objectifs, interruptions, patterns factuels. Si le seuil n'est pas atteint : **`Données insuffisantes`** avec la raison, sans chiffre inventé.

## Règles UX

1. Par défaut, l'onglet Coach ouvre **Conversation** (aucune régression des tests Coach existants).
2. Segmented control compact `Conversation | Synthèses`, puis `Jour | Semaine | Mois`. Deux taps maximum pour atteindre une synthèse.
3. Une synthèse = 3 à 5 lignes maximum par défaut : chiffre principal + une observation. Le détail (liste des activités, habitudes) est replié sous `Détails`.
4. Texte total de l'écran Synthèses ≤ ~15 lignes visibles hors détail. Pas de paragraphe d'introduction long ; une ligne « Synthèses locales, sans envoi » suffit.
5. `Données insuffisantes` est un état de premier plan, pas une erreur ; afficher la raison (ex. « moins de 3 jours de données sur 7 »).
6. Aucune nouvelle permission, aucun envoi réseau, aucun accès UsageStats. Les sources sont uniquement Focus, habitudes, plan local, objectifs et journal d'effets déjà consentis.
7. Accessibilité : tags de test, police 2×, cibles ≥ 48 dp, pas de tableau à défilement horizontal.
8. **Ne pas modifier `AgentCoachScreen.kt`** : le wrapper `CoachTabScreen` compose l'écran existant. `AtlasApp` route `AtlasScreenId.COACH` vers `CoachTabScreen`.
