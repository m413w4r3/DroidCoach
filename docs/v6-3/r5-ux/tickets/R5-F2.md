## Objectif observable

Appliquer le même régime que `R5-F` aux écrans secondaires : **Plan**, **Partage backend**, **Connexion relayée**, **Paramètres**, **Sport**. Une ligne par défaut, détail sur demande. Aucune information de consentement, permission, révocation, erreur TLS, refus ou confirmation ne disparaît.

## Règles

1. **Conserver** intégralement le sens des textes de sécurité : consentements backend/localisation, révocation, erreurs TLS/401, permission UsageStats, rôle HOME, suppression d'historique, confirmations de révision de plan. Les raccourcir ou les placer au moment de l'action, jamais les supprimer.
2. **Plan** : intro/notes techniques sous `Options` ou `Détails` ; le hero, le sélecteur Aujourd'hui/Demain, `Ajouter une activité`, `Demander au coach` et la liste restent inchangés. Les aperçus de révision et confirmations restent visibles avant application.
3. **Connexion relayée** : état humain + PC appairé visibles ; URL, `serverId`, clé X25519, UUID, jeton dans `Avancé` (déjà le cas) ; toute erreur TLS/révocation/consentement reste visible. Réduire l'intro à une ligne.
4. **Partage backend** : statut et catégories visibles ; configuration technique et purges sous `Configuration avancée` ; erreurs visibles ; réduire les paragraphes d'intro.
5. **Paramètres** : réduire le paragraphe d'introduction et le texte du rôle HOME à une phrase chacun ; les boutons et avertissements restent. Ne pas toucher aux autres fonctions de `AtlasScreens.kt`.
6. **Sport** : état humain d'abord, source/synchronisation sous `Détails`, conserver les sections séance/résultats et les erreurs.
7. **Préserver les test tags** existants de ces écrans. Si un tag ne peut être conservé, le documenter et le justifier ; ne pas modifier les tests existants.
8. **Aucune nouvelle permission, capability, navigation ou requête réseau.**
