## Findings

### P2 — identifiants de sessions internes non expurgés

Le registre conserve plusieurs UUID de sessions à [V7-11_TASK_REGISTRY.md:47](V7-11_TASK_REGISTRY.md:47). Aucun n’est reproduit dans ce rapport. Le scan n’a pas détecté de serial physique, secret, bearer, chemin machine réel ou donnée personnelle dans le périmètre demandé.

### P2 — durabilité et atomicité insuffisantes dans le restore manuel proposé

Le restore manuel remplace les trois fichiers l’un après l’autre avec `os.replace`, sans `fsync` des fichiers ou répertoires et sans rollback automatique si le processus s’interrompt au milieu ([V7-11B_CONNECTOR_BACKUP_EVIDENCE.md](V7-11B_CONNECTOR_BACKUP_EVIDENCE.md:195)). Une panne peut donc laisser un état mixte ou non durable. L’arrêt du service et la vérification des trois hashes avant redémarrage réduisent le risque d’écriture concurrente, mais ne rendent pas le remplacement multi-fichier atomique.

La destination de backup est contrôlée comme absente puis créée séparément dans le helper manuel ; le code CLI suit également un contrôle `lstat` suivi de `mkdir` ([V7-11B_CONNECTOR_BACKUP_EVIDENCE.md](V7-11B_CONNECTOR_BACKUP_EVIDENCE.md:130), [state-backup.mjs](../../../integrations/relay/pc/scripts/state-backup.mjs:13)). C’est une fenêtre TOCTOU pour une création concurrente. Les répertoires privés `0700` et le contexte opérateur bornent l’exposition, sans supprimer le risque d’une course entre processus du même compte.

Aucune fenêtre de permission manifeste n’est démontrée : l’extrait shell impose `umask 077`, puis `chmod 0600`; le CLI crée le manifeste avec le mode `0600` ([V7-11B_CONNECTOR_BACKUP_EVIDENCE.md](V7-11B_CONNECTOR_BACKUP_EVIDENCE.md:119), [state-backup.mjs](../../../integrations/relay/pc/scripts/state-backup.mjs:33)). Le flag CLI `--service-stopped` reste une attestation opérateur, pas une détection du service ([V7-11B_CONNECTOR_BACKUP_EVIDENCE.md](V7-11B_CONNECTOR_BACKUP_EVIDENCE.md:103)).
